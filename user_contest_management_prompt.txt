Create a React Container and components using Typescript that allows a user to schedule a Competition flight in a navigation task that is part of a contest. It should be mobile first and use the DaisyUI component library with Tailwind. The container should be integrated with the existing router EditableRouteRouter.

The available contests are fetched from the URL in the following variable: document.configuration.CONTESTS_LIST_URL

Scheduling a flight is a two step process that consists of first signing up to the contest and then scheduling a flight. We want to represent this as a single step in the user interface by hiding the contest sign up step. Signing up to the contest is a Team Registration. The user creates a contest team registration where they provide an optional copilot, the aircraft registration, the desired airspeed, and the club they will be flying for.

Scheduling a flight in a contest where the user already has signed up requires the user to enter The starting point time the wind direction, and the wind speed. The user can also indicate whether this should be an adaptive start. If adaptive start is selected, your start time will be set to the nearest whole minute you cross the 10 NM long line going through the starting gate anywhere between one hour before and one hour after the selected starting point time (FAQ).
Scheduling a flight is achieved puting the following data block to the end point navigationTaskContestantSelfRegistration: (contestId, navigationTaskId)
{
    "starting_point_time": "2025-12-31T15:42:00.371Z",
    "contest_team": 4934,
    "adaptive_start": false,
    "wind_speed": 0,
    "wind_direction": 0
}


To combine the and flight scheduling steps into a single step we need a single form. If the user is Not already signed up the contest it must be prompted select a copilot, and enter aircraft airspeed and club. If the user is already registered These fields should be prefilled with the existing registration.

The Fields co-pilot, aircraft, and club It should support auto completion. For clubs the list of available clubs can be fetched from the endpoint /api/v1/clubs/ Which returns to the list of available clubs where a single object looks like:
{
    "id": 15,
    "country_flag_url": "https://storage.googleapis.com/airsports-static/flags/no.gif",
    "country": "NO",
    "name": "Gjøvik og Toten Flyklubb",
    "logo": "https://storage.googleapis.com/airsports-data/gjovik_wHfePG0.jpg"
}
The user should be free to enter a club that is not already in the list.

For aircraft The list of available aircrafts can be fetched from the end point api/v1/aircraft/ Which returns the list of available aircraft where a single object looks like: 
{
    "id": 203,
    "registration": "G-DWCB",
    "colour": "Red",
    "type": "Chilton",
    "picture": null
}
The user should be free to enter a aircraft that is not already in the list.

For the copilot, the list of available copilots can be fetched from /display/api/person/signuplist/ Which returns the list of available copilots wear a single object looks like:
{
    "id": 224,
    "first_name": "Petter",
    "last_name": "Faye-Lund",
    "email": "petter@*****.no"
}
The user is not permitted to enter copilots that are not available in the list.

When entering the main page the user should be provided with a list of contests where the end date is in the future. Each contest should display the available navigation tasks and the user should be able to click a navigation task to schedule a flight (With the implicit contest registration). The user should easily a list upcoming scheduled flights. The user should be able to easily cancel a scheduled flight. It would be nice to highlight any contests where the user is already registered.
